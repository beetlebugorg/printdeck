Printdeck OS

A small, read-only Linux system for the Printdeck, with two system slots.

A small Linux system for the Printdeck Raspberry Pi 5. It holds only what Printdeck needs:

  • The Printdeck program (deck/), one static program with no other files: the Klipper host (a Go port of klippy, at the version of the printer's firmware), the touch screen, a web page for phones, the remote screen in the browser, an OctoPrint-compatible API for slicers, and the system programs of the image
  • Wi-Fi, mDNS (printdeck.local) and NTP

It has no package manager, no Docker, no compiler, no shell and no SSH. Buildroot makes the system from source. The Printdeck program is one static Go binary, on the standard parts of a small Linux system (systemd, wpa_supplicant). See ARCHITECTURE.md in the top folder.

The debug image is the same system with SSH, sudo, a shell and tools such as strace and tcpdump. Use it to develop and to find problems.

Install

The image works on an SD card and on a USB SSD. Write it with Raspberry Pi Imager ("Use custom"), or with xz and dd:

xz -dc os/out/printdeck.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

A Pi 5 starts from USB when no SD card is in it. To set this, run sudo raspi-config on Raspberry Pi OS: Advanced Options > Boot Order.

The first start

The touch screen shows the Printdeck start screen until the Printdeck program starts. To see the boot messages instead, hold a finger on the screen for one second during the start. Then the touch screen program does not start, so the messages stay. Start the Pi again to go back.

The first start makes the data partition fill the disk, and makes the login (see below). Then the touch screen opens the setup screen:

  1. The Wi-Fi networks show. Tap one and type its password, or tap Hidden for a network that is not in the list. The list scans again by itself.
  2. The summary shows the address of the Printdeck and the password of its web pages. The debug image also shows the user name and the SSH command.

To see the summary again, open Print > Control > Help. The Help screen also has a button for the Wi-Fi.

You can also set up before the first start. Put the disk in a computer and open the PRINTDECK partition. Fill in printdeck.txt:

SettingWhat it does
wifi_ssid, wifi_password, wifi_countryThe Wi-Fi network. The Pi clears the password in the file after it reads it.
ssh_keyA public SSH key for the user printdeck (debug image only)
printer.cfg (a file, next to printdeck.txt)The Klipper configuration (see "Klipper")
hostname, timezoneThe name on the network (printdeck.local) and the time zone
display_rotate, touch_invert_x, preheat_tool, ...The settings of the touch screen (see "Settings")

The login

At the first start, printdeck-credentials makes a random password of four words, for example stamp-ocean-cider-brick. The words come from the EFF short word list, so the password is easy to type and has about 41 bits of randomness. The password logs in to the web pages. In the debug image, it is also the password of the user printdeck for SSH and sudo.

The touch screen shows the password on the Help screen (Print > Control > Help). The password is in /var/lib/printdeck/password.

The web pages

Open http://printdeck.local in a browser and log in with the password. The web server uses plain HTTP, so use it only on your own network. It has two pages:

  • /: the Printdeck UI, with all the screens of the touch screen. Each browser has its own session of the UI: the deck draws it for that browser and sends the drawing commands, and the browser draws them at the pixel density of its screen. The height of the UI follows the shape of the window, so the tab bar of a phone is at the bottom. On a phone, "Add to Home Screen" makes it an app with no browser bars.
  • /system: the version, the slot, the memory, the services, the system log and the Klipper log, the API key for slicers, the update (see "Update"), and the link to the source code of the running version, because Printdeck is under the AGPL-3.0.

Slicers

The Printdeck answers the OctoPrint API that slicers use to send files and start prints. The slicers see a printer named "Printdeck". The API is on port 80, and the files go to the folder of Klipper's virtual SD card (/var/lib/klipper/gcodes). Klipper then prints the file itself.

  • Cura (the OctoPrint Connection plugin): the Printdeck shows in the list of OctoPrint printers. Select it and tap "Request". The touch screen asks "Allow Cura to use the Printdeck?". Tap Allow.
  • OrcaSlicer, PrusaSlicer: add a physical printer of the type OctoPrint, with the address http://printdeck.local. The API key is on the system page (/system).

The touch screen shows the uploads in the file list of the Print tab.

The webcam of the API is the USB camera of the deck (Machine > Settings > Camera), or the screen of the deck when it has no camera:

  • /webcam/stream: an MJPEG stream. fps=2 sends at most 2 frames a second. The default is the rate of the camera, up to 15 frames a second.
  • /webcam/snapshot: the newest frame as a JPEG.
  • w=320 (both): a smaller picture, 320 pixels wide, with the same shape. The viewers of one width share one JPEG for each frame.

They need the API key (X-Api-Key, or ?apikey=), or the login of the remote screen. The camera runs only while somebody looks, and stops 8 seconds after the last viewer, so the first snapshot takes up to a second more. /api/plugin/printdeck tells the camera: its name, its state, and the size and the rate of its frames.

Klipper

The Klipper configuration is /var/lib/klipper/config/printer.cfg. To bring your own, put it on the PRINTDECK partition as printer.cfg, from any computer. At the next start, the Pi copies it to Klipper and renames the file on the partition to printer.cfg.imported. So a later SAVE_CONFIG on the Pi stays.

The last line of printer.cfg must include the sections that Printdeck needs. The import adds it:

[include /usr/share/printdeck/klipper/printdeck.cfg]

That file sets [virtual_sdcard] to the upload folder, and adds [pause_resume] and [display_status]. It must be the last line, because Klipper uses the last value of a setting: then the upload folder wins over a [virtual_sdcard] path of another setup. If your configuration has a CANCEL_PRINT macro, the Cancel button runs it.

The printer's board keeps its firmware. The Klipper version in deck/internal/klipper/klipper.version must match the firmware on the board. The klipper service runs the host: printdeck klippy, with the options of klippy.py.

A simulated printer

The deck can run a simulated printer with no printer and no cable. Klipper then runs the config of a real printer with serial: sim: the board of the printer runs in the Klipper host. It heats, homes, probes and prints in real time, and no motor moves.

  1. Open Machine, then Simulated printer. The setup screen of a deck with no printer has the same key.
  2. Tap a printer: the LulzBot TAZ Workhorse, the LulzBot Mini 2, or the Creality CR-10 V3. Klipper restarts.
  3. To stop, tap Real printer on the same page. Klipper restarts with your config.

The deck moves your printer.cfg to printer.cfg.real, and writes the config of the simulated printer as printer.cfg. Real printer moves printer.cfg.real back with no change. An orange band at the top of each screen shows the simulated printer. The configs are in the program (deck/internal/printer/sim/), and make.sh there makes them again.

Settings

The settings of the Printdeck program are in /etc/printdeck/deck.env, for example the screen rotation, the touch axes and the preheat temperatures. To change one, put it in printdeck.txt in lower case, for example display_rotate=90, and start the Pi again. printdeck-settings writes these settings to /var/lib/printdeck/settings.env, which the deck reads after deck.env. The release image needs no SSH for any setting.

The Screen row of Settings (on the Machine page) turns the screen a quarter turn and restarts the deck. The deck keeps that turn in /var/lib/printdeck/rotate, and it wins over display_rotate.

Update

The disk has two system slots, A and B. The running system stays as it is while an update writes the other slot. Open http://printdeck.local/system, choose printdeck-update.tar.xz (or printdeck-debug-update.tar.xz), and click Install. The page refuses an update during a print. With curl:

curl -c cookies -d password=PASSWORD http://printdeck.local/login
curl -b cookies -F bundle=@os/out/printdeck-update.tar.xz http://printdeck.local/system/update

The debug image can also install a bundle over SSH: sudo printdeck-update FILE.

The Pi restarts into the new slot one time. If Klipper and the touch screen start, the new slot becomes the default. If they do not start, or the system stops, the Pi starts the old slot again.

How it works

PartitionFile systemContents
1 PRINTDECKFATautoboot.txt (the A/B switch) and printdeck.txt
2 boot A, 3 boot BFATKernel, device trees, overlays, config.txt, cmdline.txt
4 root A, 5 root BEROFSThe system, read-only
6 dataext4The changes to /etc, /var, /home and /root. It fills the disk after the first start.

The root file system is read-only. At the start, printdeck-init mounts the data partition and puts a writable layer from it over /etc, /var, /home and /root. It starts the start screen (printdeck splash), and then systemd. To reset the system, delete the files in the data partition. If printdeck-init cannot continue, it writes the kernel log to printdeck-boot.log on the PRINTDECK partition. After an update, it then restarts into the old slot. Otherwise the debug image starts a shell on the console, and the release image waits.

The Pi firmware selects the slot with autoboot.txt and its tryboot mode. printdeck-update writes the other slot and restarts with tryboot. printdeck-commit changes autoboot.txt after a good start. panic=10 on the kernel command line restarts the Pi after a kernel panic, so a new slot that stops at the start goes back to the old slot too.

The system programs (printdeck-init, -update, -commit, -credentials, -settings and -wifi) are links to the Printdeck program, which runs the program of the name. The deck runs as the user deck. For the actions that need root (the Wi-Fi, a restart of Klipper, an update), it asks the system helper (printdeck helper) on a socket that only the group deck can open.

The journal is on the data partition (/var/log/journal), so the logs of the last starts stay. To read them on another computer, copy the folder and run journalctl --directory.

The boot partitions have the overlays from the kernel build, so they match its device trees. The Pi 5 with the D0 chip needs overlays/bcm2712d0.dtbo: the firmware applies it by itself, and without it the kernel stops at boot.

Size

The image keeps only what Printdeck uses:

  • No Python: the Printdeck program has the Klipper host.
  • No sound: no ALSA library and no sound drivers. The kernel keeps only the sound core, because the display driver (vc4) needs it for HDMI audio.
  • The Printdeck program runs as the unprivileged user deck. It has the groups of its devices (video, input, tty, dialout, systemd-journal) and of Klipper (printer), and two capabilities: port 80 and the graphics mode of the console. The system helper does the actions that need root.
  • No shell, no BusyBox, no SSH and no sudo. board/release-prune.sh keeps a list of programs and the libraries that they link or load, and removes the other programs, libraries and units.
  • No OctoPrint: the Printdeck program has the OctoPrint-compatible API that slicers use.
  • No hardware database, console keymaps or timedated, and no command-line tools that come with libraries (for example sqlite3, flac, systemd-nspawn).
  • Only the Wi-Fi firmware of the Pi 5, and no Bluetooth.
  • No libraries that no program links or loads, such as libstdc++ (board/post-build.sh).
  • The kernel has only the modules that the Printdeck uses: the display, the Wi-Fi, the USB serial ports of the printer boards, USB cameras (UVC), the fan, and the buses they use (board/linux-modules.txt). The SSD, the touch screen and the file systems are built into the kernel. The display driver (vc4) is built in too, so that the start screen has the full display from the first frame.
  • The kernel shows the start screen when the display starts (fullscreen_logo), from board/firmware/printdeck-logo.tga. The deck makes this file from its start screen: after a change to the start screen, run go test ./internal/ui -run SplashLogo -update-logo in deck, then os/build.sh linux-rebuild. board/linux-patches has a fix for the logo code of the kernel.
  • The kernel modules are not compressed, because Buildroot's depmod cannot read compressed modules, and EROFS compresses the root file system already.

The kernel config

board/linux.config is the bcm2712 defconfig of the Raspberry Pi kernel, reduced with make localmodconfig to the modules of board/linux-modules.txt. To add a module, add its name to board/linux-modules.txt, then make the config again in the kernel folder of the build:

cd ~/.cache/printdeck-os/output/build/linux-custom
make ARCH=arm64 bcm2712_defconfig
make ARCH=arm64 LSMOD=/path/to/os/board/linux-modules.txt localmodconfig
make ARCH=arm64 savedefconfig   # then copy defconfig to board/linux.config

Then set these options to y in board/linux.config, because localmodconfig makes them modules: CONFIG_DRM, CONFIG_DRM_VC4, CONFIG_SND, CONFIG_SND_SOC and CONFIG_I2C_BRCMSTB.

The build container has the tools: run the commands in it, with the cross compiler of output/per-package/linux/host/bin in PATH and CROSS_COMPILE=aarch64-linux-.
