What the program does

The Printdeck runs Printdeck OS: a small, read-only Linux system that Buildroot makes from source. os/README.md tells how to build it, write it to a disk, set it up, and update it. It has:

  • deck/, the Printdeck program (Go). It is one static binary with no cgo. It runs as the user deck, and does these things:
    • printdeck klippy is the Klipper host, a Go port of Klipper's klippy.py. The klipper service runs it in its own process. It drives the printer. deck/internal/klipper/PORTING.md tells how the port follows Klipper.
    • It draws the full screen application on the 7" display, without a desktop or a browser.
    • It serves the remote screen at http://printdeck.local: the touch screen in a browser, with the password of the printdeck user.
    • It serves the part of the OctoPrint API that slicers use. Cura, OrcaSlicer and PrusaSlicer see a printer named "Printdeck", upload files to it, and start prints. Cura gets its key with a tap on the touch screen.
    • It follows the Klipper host through its API socket.
    • It draws the display of the printer (128 x 64) with the printdeck_display module of the Klipper host. The knob of the printer opens the same menus as the touch screen.

The screens are on the deck UI pages. The commands of the program are in the reference.

The goal

Printdeck is a very small operating system with one purpose: run one 3D printer and its touch screen. The goals are a small image, a fast start, and a low use of memory and CPU.

The Printdeck program is one static Go binary with no runtime dependencies: no shared libraries, and no other programs for its work. cgo is allowed only when it links statically. Today the binary builds with CGO_ENABLED=0.

The system parts stay as they are: the kernel and its firmware, systemd, wpa_supplicant, Dropbear, sudo and the CA certificates. Buildroot makes the image.

The Klipper port

A Go Klipper host can drive a heater or a motor in the wrong way. So the port follows these rules:

  • It starts from the Klipper commit that the printer's firmware has, and keeps the same protocol.
  • The heater safety code (the PID loop, verify_heater, and the limits that the host gives the firmware) comes first.
  • The Go host must give the same board commands as Klipper's batch mode (klippy.py -o) for the printer of printer/, before it drives the printer. Klipper's own runs differ in the order of the commands of different objects, so the test compares the commands of each object, in order. tools/klipper-reference makes the reference data, and deck/internal/klipper/PORTING.md has the rules of the port.

Open source and licenses

Printdeck stands on the work of other open source projects: Klipper, OctoPrint, Moonraker, Buildroot and the Linux kernel. We do not take their code to hide it. We reform it into a small, single-purpose system, in the spirit of open source, and we give the result back under a compatible license.

Every effort is made to respect the licenses:

  • Printdeck is licensed under the GNU Affero GPL, version 3 (LICENSE). Printdeck is a network device, so the AGPL also gives the source to people who use it over the network. The remote screen links to the source.
  • Klipper is GPL-3.0. Section 13 of the GPL-3.0 and of the AGPL-3.0 lets its code and Printdeck's code be one program. Its files keep the GPL-3.0. OctoPrint is AGPL-3.0, the same as Printdeck.
  • Code that is ported from another project keeps its copyright and license notices, and names the project and its authors at the top of the file. For example, internal/klippy names Klipper's webhooks.py and its author.
  • Where we only speak a protocol (the OctoPrint API for slicers, the Klipper API socket), we write our own code from the documentation and the behaviour, and say which project defines the protocol.
  • A release of the image includes the sources and the licenses of all its packages (make legal-info of Buildroot).
  • The proprietary firmware of the Pi and of the Wi-Fi chip is redistributable under its own licenses, and the image keeps those licenses.

If you find code in Printdeck without the credit or the license that it needs, please open an issue.

Built with AI

Much of Printdeck is written with an AI coding assistant (Claude), directed and reviewed by a person. The same rules apply to that code: it must respect the licenses above, give credit where it ports or follows other code, and pass its tests.

Demo mode

To look at the screens without the hardware, run go run ./cmd/printdeck demo /tmp/shots in deck/. It writes PNG files. To use the screens in a browser, run go run ./cmd/printdeck remote-demo and open http://localhost:8080 (password demo).
