The remote screen and the API

The deck in a browser, the system page, and the OctoPrint-compatible API that slicers use.

On this page
  1. The remote screen
  2. The API for slicers

The remote screen

Open http://printdeck.local in a browser and log in with the password. The web server uses plain HTTP, so use it only on your own network. It has two pages:

  • /: the Printdeck UI, with all the screens of the touch screen. Each browser has its own session of the UI: the deck draws it for that browser and sends the drawing commands, and the browser draws them at the pixel density of its screen. The height of the UI follows the shape of the window, so the tab bar of a phone is at the bottom. On a phone, "Add to Home Screen" makes it an app with no browser bars.
  • /system: the version, the slot, the memory, the services, the system log and the Klipper log, the API key for slicers, the update (see "Update"), and the link to the source code of the running version, because Printdeck is under the AGPL-3.0.

Package remote is the deck UI in a web browser: each browser has its own session of the UI, and draws its frames on a canvas. The password of the Printdeck login protects it.

The API for slicers

The Printdeck answers the OctoPrint API that slicers use to send files and start prints. The slicers see a printer named "Printdeck". The API is on port 80, and the files go to the folder of Klipper's virtual SD card (/var/lib/klipper/gcodes). Klipper then prints the file itself.

  • Cura (the OctoPrint Connection plugin): the Printdeck shows in the list of OctoPrint printers. Select it and tap "Request". The touch screen asks "Allow Cura to use the Printdeck?". Tap Allow.
  • OrcaSlicer, PrusaSlicer: add a physical printer of the type OctoPrint, with the address http://printdeck.local. The API key is on the system page (/system).

The touch screen shows the uploads in the file list of the Print tab.

Package octoapi serves the part of the OctoPrint REST API that slicers use, so Cura, OrcaSlicer, PrusaSlicer and others can send files to the Printdeck and start prints. The Printdeck shows its own name, and says "OctoPrint" only in the version text that the slicers check.

The API is defined by OctoPrint (https://docs.octoprint.org/en/master/api/, AGPL-3.0). This is our own code: it follows the documentation and the requests of the slicers, and has none of OctoPrint's code. Moonraker's octoprint_compat.py (GPL-3.0) showed which endpoints the slicers need.

The Printdeck plugin for Cura uses the same connection, and the /api/plugin/printdeck routes.
