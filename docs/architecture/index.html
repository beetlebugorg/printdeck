Architecture

Architecture

This document describes the parts of the Printdeck system and how they connect. It explains how each deck, person, page and GitHub Action proves who it is. It shows why the passkey sign-in and the builds from GitHub are secure, and where their limits are.

Download the PDF (1.9 MB) Read it on the site

The document describes the system as of November 1, 2026, from the code at commit c6215969. The short version is ARCHITECTURE.md in the repository, and the page The printdeck program.

Sources. The facts come from the code at commit c6215969: cloud/api, cloud/deploy/template.yaml, cloud/cmd/pwf, cloud/cmd/pwf-web, cloud/deploy/web/assets, deck/internal/cloud, deck/internal/chitu, deck/internal/printer, deck/cmd/printdeck, deck/internal/system, os/ and profiles/. The builds from GitHub also come from docs/specs/github-builds.md and from the repository beetlebugorg/printdeck-action at commit 4f1e056. The passkey library is github.com/go-webauthn/webauthn v0.18.2.

Words. A deck is a Raspberry Pi 5 with a touch screen that runs Printdeck OS. The owner is the person who runs the service. A member is a friend that the owner invited to one or more projects. The API is the Go program on AWS Lambda. The bucket is the S3 bucket of the service. The Action is beetlebugorg/printdeck-action in a workflow of a project repository on GitHub.
